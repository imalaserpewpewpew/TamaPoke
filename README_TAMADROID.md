# TamaDroid preview build (first droid)

This is your TamaPoke 1.43 project with the first droid wired in. Nothing about
the board support changed (display, touch, sleep, OFF button, microSD).

## What's different
- An R-series astromech replaces dex 1-3. Its restoration stages use the
  existing evolution chain: SCRAP R-UNIT (lv 1) -> R-UNIT (lv 16) -> R-UNIT MK.II (lv 32).
- Every egg holds the astromech, and the starter pick is skipped.
- The astromech's sprites are built into the firmware (builtin_sprites.h, ~165 KB),
  so it shows with NO microSD card. A card with /mons/p001-p003.bin overrides them.
- Everything is behind DROID_PREVIEW in droid.h. Set it to 0 for the original game.
- Host tests run with DROID_PREVIEW=0 (177/177 pass).

## Update 4: mini-games
The play button now opens a game menu (same panel as the food menu):
1. Blaster training: the training remote drifts along the top and fires bolts at the droid.
   Tap a bolt to deflect it. Three bolts through = round over. Trains Speed, raises FUNC.
2. Cargo lift: tap fast for 10 seconds to haul a crate up its cable. Trains Power.
3. Circuit repair: four lights flash a sequence, repeat it; one more step each round.
   Trains Armor, raises FUNC. Best round is saved (new "chi" key).
4. Canyon run: shown greyed out, not built yet (tilt game using the motion sensor).
Tap the very top of the screen to quit any game.

## Build and flash (new board, Arduino IDE + esptool-js)
The 1.43 is now the default board, so no compiler flags are needed.

1. Arduino IDE: open TamaPoke/TamaPoke.ino.
2. Tools menu: Board "ESP32S3 Dev Module", USB CDC On Boot "Enabled",
   Flash Size "16MB (128Mb)", PSRAM "OPI PSRAM",
   Partition Scheme "16M Flash (3MB APP/9.9MB FATFS)".
3. Libraries (Library Manager): GFX Library for Arduino, SensorLib, XPowersLib, U8g2.
4. Sketch > Export Compiled Binary. It writes a build/ folder next to the sketch
   with TamaPoke.ino.merged.bin.
5. https://espressif.github.io/esptool-js/ : Connect, add TamaPoke.ino.merged.bin
   at address 0x0, Program.

(tools/build_143.sh still works too.)

## Quick look at all three stages
Set MINUTES_PER_LEVEL to 1 in pet.h before building: one level per game minute,
so the droid reaches repaired after ~15 minutes and restored after ~30.
